## 二、系统架构

### 2.1 整体架构

```
┌──────────────────────────────────────────────────┐
│                   浏览器 (Chrome/Edge)            │
└──────────────────────┬───────────────────────────┘
                       │ HTTP/HTTPS
┌──────────────────────▼───────────────────────────┐
│               Nginx (生产环境反向代理)              │
│         /api/* → 后端    其他 → 前端静态资源        │
└────────┬─────────────────────────────┬───────────┘
         │                             │
┌────────▼─────────┐       ┌──────────▼───────────┐
│  前端 (Vue3 SPA)  │       │  后端 (Spring Boot)   │
│  Port: 3000       │       │  Port: 8081           │
│  ─────────────── │       │  ────────────────────  │
│  Vue Router       │──────▶│  Spring Security+JWT  │
│  Pinia Store      │ API   │  Controller → Service │
│  Element Plus     │──────▶│       → Mapper        │
│  ECharts          │       │  AOP(操作日志)         │
│  xlsx(导出)       │       │  EasyExcel(导入)       │
└───────────────────┘       └──────────┬───────────┘
                                       │
                            ┌──────────▼───────────┐
                            │   SQLite 数据库       │
                            │   data/linxi.db       │
                            │   ──────────────      │
                            │   28张表 + 索引       │
                            └──────────────────────┘
```

### 2.2 后端分层架构

```
Controller (REST API)
    │
    ├── @PreAuthorize (权限校验)
    ├── @OperationLog (操作日志)
    │
    ▼
Service (业务逻辑)
    │
    ├── 事务管理
    ├── 数据校验
    ├── 自动计算（FormulaCalculator）
    │
    ▼
Mapper (MyBatis-Plus)
    │
    ├── BaseMapper<T> (通用CRUD)
    ├── XML Mapper (自定义SQL)
    │
    ▼
Entity → SQLite
```

### 2.3 前端架构

```
App.vue
    │
    ├── Login.vue (无需认证)
    │
    └── MainLayout.vue (需认证)
         ├── 侧边栏 (el-menu, 菜单从API加载)
         ├── 顶部栏 (折叠按钮 + 标题 + MessageBell + 用户下拉)
         └── 内容区 (router-view)
              │
              ├── views/ (24个页面组件)
              ├── components/ (4个公共组件)
              ├── api/ (9个API模块)
              └── store/ (Pinia用户状态)
```

### 3.4 数据库设计特征

#### 3.4.1 双存储架构

日报数据采用**列式+EAV双存储**并行的架构：

| 存储方式 | 对应表 | 特点 | 使用场景 |
|---------|--------|------|---------|
| 列式存储 | daily_report + daily_channel + daily_extension | 查询性能高，字段固定 | 日报列表查询、报表统计 |
| EAV存储 | daily_report_value | 灵活扩展，无需改表 | 动态字段配置、评分排名查询 |
| 行式存储 | daily_report_channel + daily_report_platform | 支持动态渠道 | 渠道分析、平台评价 |

#### 3.4.2 软删除模式

核心业务表均采用 `deleted` 字段逻辑删除：
- daily_report, store, investor, daily_report_template, sys_user, sys_config
- MyBatis-Plus全局配置：`logic-delete-value: 1, logic-not-delete-value: 0`

#### 3.4.3 条件唯一索引

SQLite不支持NULL值的UNIQUE约束，采用条件索引：
- `uk_investor_phone` → `WHERE phone IS NOT NULL`
- `uk_phone` (sys_user) → `WHERE phone IS NOT NULL`

#### 3.4.4 时间字段处理

- 部分表使用 `VARCHAR(50)` 存储时间字符串
- 部分表使用 `TEXT DEFAULT (datetime('now','localtime'))` 自动填充
- 前端日期格式：`yyyy-MM-dd HH:mm:ss`
- Jackson全局配置：`date-format: yyyy-MM-dd HH:mm:ss, time-zone: GMT+8`

## 七、安全设计

| 菜单级 | 角色菜单关联(sys_role_menu) | 控制用户可见菜单 |
| 接口级 | @PreAuthorize | 基于角色(hasRole)或权限码(hasAnyAuthority) |
| 数据级 | sys_user_store | 控制用户可访问的门店数据范围 |
| 投资者级 | investor_store | 控制投资者可查看的投资门店 |

## 八、关键设计决策

### 8.1 日报数据双存储

**决策**：日报数据同时存储在列式表（daily_report）和EAV表（daily_report_value）中。

**原因**：
- 列式存储查询性能高，适合报表统计和列表展示
- EAV存储灵活扩展，支持动态字段配置，无需改表结构
- 渠道/平台数据从列式改为行式存储（V1→V2迁移），支持动态扩展渠道

**迁移历史**：
- V1: 日报渠道/平台数据在daily_report列中 → 拆分为daily_report_channel + daily_report_platform行式表
- V2: 补齐daily_extension历史记录(2851条)
- V3: investor_store增加invest_amount投资金额字段

### 8.2 渠道数据行式存储

**决策**：渠道间夜和平台评价采用行式存储（一条日报×一个渠道/平台=一条记录）。

**原因**：
- 支持动态扩展渠道，新增渠道无需改表
- 适合渠道分析和占比计算
- 与旧版列式存储（daily_channel）并行，保持向后兼容

### 8.3 日期维度表

**决策**：建立dim_date日期维度表，覆盖4年。

**原因**：
- SQLite不支持ISO周函数，需要预计算周号
- 同比对比需要精确定位去年同期对应周期
- 时间维度（天/周/月）切换需要统一的日期分组

### 8.4 投资人自动开户

**决策**：新增投资人时自动创建系统用户账户。

**实现**：
1. 以手机号为用户名创建sys_user
2. 默认密码123456
3. 自动分配INVESTOR角色(roleId=6)
4. 创建投资关系时同步添加sys_user_store
5. 删除时级联清理

### 8.5 操作日志AOP

**决策**：通过自定义注解+AOP切面自动记录操作日志。

**实现**：
- `@OperationLog(module, type, description)` 注解标记需要记录的方法
- `OperationLogAspect` 切面拦截，自动获取操作人、IP、请求参数、结果状态
- 登录操作特殊处理：通过反射从方法参数获取用户名

### 8.6 报表加权平均

**决策**：出租率、ADR、RevPAR在汇总时采用加权平均而非简单算术平均。

**公式**：
- 均出租率 = Σ(各门店间夜数) / Σ(各门店自有房量) × 100
- 均ADR = Σ(各门店日租房费) / Σ(各门店间夜数)
- 均RevPAR = Σ(各门店总营收) / Σ(各门店自有房量)
