## 一、项目概述

### 1.1 项目背景

林夕置业是一家酒店联营公司，旗下管理多个酒店门店（当前9家，均位于深圳）。系统上线前，各门店通过 Excel 日报表方式记录每日经营数据，存在数据分散、人工汇总易出错、投资者无法便捷查看、权限隔离不足等问题。

### 1.2 产品定位

**"门店填报、总部监管、投资者查看、权限隔离、报表分析、字段可扩展"** 的酒店经营数据管理平台。

### 1.3 系统建设范围

| 类别 | 包含内容 |
|------|---------|
| **本期已实现** | 登录认证、首页工作台、门店管理、用户管理、角色权限管理、日报管理（填报+查询+审核）、日报模板配置、字段配置、未填报统计、经营分析（总部看板/日报/月报/渠道/排名/趋势）、投资人管理、站内消息、系统配置、操作日志、数据导入 |
| **本期未纳入** | PMS系统对接、OTA渠道自动拉取、财务凭证、审批流引擎、多租户SaaS、手机App/小程序、投资者分红计算、门店预算管理、AI经营分析 |

### 1.4 技术架构概览

| 层次 | 技术选型 |
|------|---------|
| 前端 | Vue 3.4 + Vite 7 + Element Plus 2.5 + Pinia 2.1 + ECharts 5.5 |
| 后端 | Spring Boot 2.7.18 + MyBatis-Plus 3.5.5 + Spring Security + JWT |
| 数据库 | SQLite（开发环境） |
| 部署 | 前后端分离，后端端口8081，前端端口3000 |

## 二、用户角色与权限体系

### 2.1 角色定义

| 角色ID | 角色编码 | 角色名称 | 角色类型 | 使用对象 | 主要职责 |
|--------|---------|---------|---------|---------|---------|
| 1 | SUPER_ADMIN | 超级管理员 | 1 | 技术管理员/系统维护 | 系统初始化、用户管理、角色权限配置、字段配置 |
| 2 | CEO | CEO/总部管理层 | 2 | 公司CEO、总部经营管理人员 | 查看全部门店经营数据、报表、门店排名、审核日报 |
| 3 | REGION_MANAGER | 区域/运营管理 | 3 | 区域负责人、运营人员 | 查看授权范围内门店数据，跟进日报填报（已定义，暂未分配用户） |
| 4 | STORE_MANAGER | 门店店长 | 4 | 各门店负责人 | 每日录入日报、查看本门店经营数据 |
| 5 | STORE_STAFF | 门店员工 | 5 | 前台、财务、运营人员 | 协助填报或查看本门店数据 |
| 6 | INVESTOR | 投资者 | 6 | 门店投资人/股东 | 查看投资门店的经营数据和报表（只读） |

### 2.2 用户类型

| userType | 含义 | 对应默认角色 |
|----------|------|-------------|
| 1 | 管理员（总部） | SUPER_ADMIN |
| 2 | 门店用户（店长/文员） | STORE_MANAGER / STORE_STAFF |
| 3 | 投资人 | INVESTOR |

### 2.3 权限模型

系统采用 **用户-角色-菜单权限** + **用户-门店数据权限** 的双重权限控制：

1. **菜单权限**：通过 `sys_role_menu` 关联角色与菜单，用户只能看到被授权的菜单
2. **数据权限**：通过 `sys_user_store` 关联用户与门店，用户只能操作/查看授权门店的数据
3. **投资者权限**：通过 `investor_store` 投资关系表控制，投资人只能查看投资门店数据
4. **按钮权限**：菜单表中 `menu_type=3` 的按钮级权限，用于控制具体操作（如审核、导出）

## 三、功能模块详述

### 模块1：登录与认证

#### 1.1 功能描述

提供系统入口的身份验证功能，确保只有合法用户可以进入系统。

#### 1.2 功能清单

| 功能项 | 说明 | 当前实现状态 |
|--------|------|:----------:|
| 用户名+密码登录 | 输入用户名和密码进行登录 | ✅ |
| 登录失败锁定 | 连续5次失败后锁定10分钟 | ✅ |
| JWT Token认证 | 登录成功生成JWT Token，后续请求携带Token | ✅ |
| Token自动续期 | Token有效期7天 | ✅ |
| 退出登录 | 清除Token，跳转登录页 | ✅ |
| 登录状态保持 | Token存储在localStorage，页面刷新不丢失 | ✅ |
| 401自动跳转 | Token过期或无效时自动跳转登录页 | ✅ |
| 403权限提示 | 无权限访问时提示"没有访问权限" | ✅ |

#### 1.3 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| AUTH-01 | 密码加密存储 | BCrypt算法加密，数据库不可逆 |
| AUTH-02 | 默认密码 | 新用户/重置密码后默认为 `123456` |
| AUTH-03 | 登录失败计数 | 基于用户名计数，内存暂存（ConcurrentHashMap），重启后清零 |
| AUTH-04 | 锁定参数可配置 | 最大失败次数和锁定时间通过 `sys_config` 表配置 |
| AUTH-05 | Token内容 | 包含 userId、username、realName、roles、permissions |
| AUTH-06 | 密码重置 | 管理员可重置用户密码为默认密码 |

#### 1.4 接口列表

| 方法 | 路径 | 功能 | 权限 |
|------|------|------|------|
| POST | /api/auth/login | 用户登录 | 公开 |
| POST | /api/auth/logout | 用户登出 | 认证 |
| GET | /api/auth/userinfo | 获取当前用户信息 | 认证 |

#### 1.5 页面要素

- **登录页**（`/login`）：蓝色渐变背景、居中白色卡片、用户名+密码表单、回车提交、loading状态

| 功能项 | 说明 | 状态 |

#### 5.2 功能清单

### 模块6：日报管理

#### 6.1 功能描述

系统的核心业务模块，实现日报从填报到审核的完整生命周期管理。当前已将原"日报填报"和"日报查询"合并为统一的"日报管理"入口。

#### 6.2 日报状态流转

```
未填报 → 草稿(0) → 已提交(1) → 已锁定(2)
                  ↘ 已退回(3) → 草稿(0) → ...
                         ↑
                    已提交(1) → 退回 → 已退回(3)
已锁定(2) → 解锁 → 已提交(1)
```

| 状态 | 值 | 说明 | 可执行操作 |
|------|---|------|-----------|
| 草稿 | 0 | 已保存未提交 | 编辑、提交、删除 |
| 已提交 | 1 | 已提交待审核 | 锁定、退回 |
| 已锁定 | 2 | 审核通过不可修改 | 解锁 |
| 已退回 | 3 | 审核退回需修改 | 编辑、重新提交 |

#### 6.3 功能清单

| 功能项 | 说明 | 状态 |
