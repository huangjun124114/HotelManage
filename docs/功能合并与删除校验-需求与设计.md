> 版本: V1.2 | 日期: 2026-05-21 | 分支: V260515

## 一、需求来源

用户提出三项优化需求：

1. 门店列表 + 门店人员功能合并
2. 投资人管理 + 投资关系配置功能合并
3. 门店删除校验 + 禁用门店约束

### 补充需求（第二轮确认）

4. 门店新增人员时需同步创建系统用户（sys_user + 绑定门店 + 分配角色）
5. 创建投资人时已自动同步创建系统用户（无需后端变更）

### 补充需求（V1.2 优化）

6. 「增加投资」按钮从投资人列表行移入投资记录弹层内部，与门店团队弹层的交互模式保持一致

## 二、需求详述

### 2.1 门店 + 团队合并

| 项 | 说明 |
|---|------|
| 入口 | 门店列表每行增加「查看团队」按钮 |
| 弹层 | 展示此门店的人员列表（姓名、手机号、角色、操作） |
| 新增人员 | 弹层内「新增」按钮 → 选择系统用户下拉 → 提交后创建 sys_user_store 关联 |
| 移除人员 | 每行「移除」按钮 → 删除 sys_user_store 关联记录 |
| 删除页面 | 删除 StoreUser.vue，移除 /store/user 路由 |

### 2.2 投资人 + 投资关系合并

| 项 | 说明 |
|---|------|
| 投资记录入口 | 投资人列表每行「投资记录」按钮 → 弹出投资记录弹层 |
| 增加投资 | 投资记录弹层内「增加投资」按钮 → 弹出新增投资关系弹层（与门店团队弹层交互一致） |
| 编辑 | 投资记录表格每行「编辑」按钮 → 弹出编辑弹层 |
| 删除 | 投资记录表格每行「删除」按钮 → 确认后删除 |
| 删除页面 | 删除 InvestorRelation.vue，移除 /investor/relation 路由 |

> **V1.2 变更**：「增加投资」按钮从列表行操作列移入投资记录弹层内部，列表行只保留「编辑」和「投资记录」两个按钮，与门店团队的交互模式统一。

### 2.3 门店删除校验

删除门店前检查以下三表：
- `investor_store`：有投资记录则拒绝
- `daily_report`：有日报记录则拒绝
- `sys_user_store`：有团队成员则拒绝

提示信息：`此门店存在投资记录/日报记录/团队记录，不能删除，但可以禁用`

### 2.4 禁用门店约束

禁用门店（status=0）不能：
- 新增团队成员（POST /api/users，后端校验）
- 新增日报（POST /api/daily-reports，后端校验）
- 新增投资记录（POST /api/investor-relations，后端校验）

前端同步校验：门店下拉已过滤 status=1，禁用门店不出现在选择列表中。

### 2.5 投资比例百分比格式

- 数据库 `investment_ratio` 字段存储百分比值（如 30.00 表示 30%）
- 前端录入：直接输入百分比数值（如输入 30 表示 30%）
- 前端显示：`formatRatio()` 函数统一格式化（30→"30%"，25.5→"25.5%"）

## 六、投资关系编辑接口参数映射

PUT /api/investor-relations/{id} 支持双重参数名：

| 前端字段 | 后端字段（备选） | 说明 |
|---------|----------------|------|
| shareRatio | investmentRatio | 持股比例（百分比） |
| investDate | authStartDate | 投资日期 |
| withdrawDate | authEndDate | 撤资日期 |
